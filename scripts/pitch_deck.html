02

Problem: 동산보험의 3가지 구조적 한계

기존 동산보험은 왜 시장 확대에 실패하는가?

1

획일적 보험료 산정

자치구별 화재율 최대 3.2배 차이에도 동일 보험료 적용. 저위험 지역 고객은 과다 납부, 고위험 지역은 과소 산정으로 손실률 악화.

2

고객 세분화 부재

1인가구 청년과 4인가구 자영업자에게 같은 상품 제안. 라이프사이클, 자산규모, 소득 수준 미반영으로 전환율 저조.

3

약관 해석의 불투명성

14개 조항, 4개 규칙의 복잡한 상호 참조 구조. 상담사도 즉답 어려워 고객 이탈 발생. 규정 근거 없는 답변은 컴플라이언스 리스크.

4

시장 기회 포착 불가

이사 시즌(3-4월, 9-10월) 동산보험 수요 급증을 실시간 감지 못함. 부동산 거래량 기반 교차판매 타이밍 놓침.

03

Solution: INSURE Platform

데이터 기반 보험료 산정 + AI 상담 + 시장 인텔리전스

STEP 2

STEP 3

보험료 엔진

7단계 비선형 커브 + 신뢰도 + 부담능력 보정

STEP 4

AI 상담

RAG 기반 약관 Q&A + Graph RAG 연결 추론

STEP 5

대시보드

시뮬레이터 + 시각화 + 실시간 모니터링

04

Architecture: 6-Layer Snowflake Pipeline

dbt 패턴 기반 데이터 파이프라인 + ML/LLM/RAG 통합

RAW (9 tables)
FIRE_STATS, CRIME_STATS, BUILDING_AGE, WEATHER_RISK, REAL_ESTATE_TX, CONSUMER_ACCIDENT, HOUSEHOLD_GOODS, PERSONA_SEGMENTS, ASSET_INCOME
STAGING (13 views)
비정규화 + 타입 캐스팅 + 별칭 정리. STG_FIRE_STATS, STG_ASSET_INCOME 등
INTERMEDIATE
INT_DISTRICT_RISK_SCORE (4요소 통합), INT_SEGMENT_CLASSIFICATION, INT_ANOMALY_DETECTION
MART
MART_DISTRICT_INSURANCE_SUMMARY, MART_PREMIUM_LAYER, MART_GENDER_AGE_CORRELATION
RAG + GRAPH
367 policy chunks (e5-base-v2 embedding) + 31 graph nodes + 34 edges (6 relationship types)
ML / LLM
Cortex FORECAST (fire prediction) + ANOMALY_DETECTION (moving season) + Mistral-Large2 (advisor) + SENTIMENT
05

Why INSURE?

기존 보험 분석 시스템 대비 차별점

7 Stage

보험료 산출 투명성

순보험료 -> 경험보험료 -> 위험분류 -> 부가보험료 -> 신뢰도보정 -> 세그먼트조정 -> 최종보험료. 모든 단계가 고객에게 공개 가능.

10 Persona

초세분화 고객 프로파일

라이프사이클(6) x 자산소비(5) x 주거(4) x 직업(3) x 위험성향(3) = 10개 대표 페르소나로 맞춤 상품 설계.

Graph RAG

약관 연결 추론

단순 키워드 검색이 아닌 "약관 -> 데이터 -> 규칙 -> 모델" 관계 그래프 기반 3-hop 추론으로 근거 있는 답변.

25

자치구별 리스크 맵

서울시 25개 자치구 화재/범죄/기상/건물 4차원 위험도를 실시간 반영. 지역별 손실률 예측 및 포트폴리오 최적화.

Z-Score

이사 시즌 자동 감지

부동산 거래량 이상치 탐지로 동산보험 수요 급증 시점 사전 포착. 교차판매 최적 타이밍 알림.

0.5%

부담능력 보호 장치

월소득 대비 보험료 상한(0.5%) 자동 적용. 과도한 보험료로 인한 고객 이탈 방지 + 금융소비자 보호 규정 준수.

Honest Value Assessment

상품 도입을 검토하는 사람 관점의 솔직한 평가

Strengths

A
기술 완성도 & 아키텍처
  • Snowflake 네이티브 풀스택 - 별도 인프라 불필요
  • dbt 패턴 파이프라인이 실무 표준에 부합
  • 7단계 보험료 엔진이 실제 보험수리 로직 반영
  • RAG + Graph RAG 이중 구조는 업계에서 드문 구현
  • 10개 페르소나 세분화는 마케팅 즉시 활용 가능
  • Cortex ML 예측 + 이상치 탐지 = 선제적 영업 가능

Gaps to Address

B
프로덕션 준비도
  • 실 보험 데이터 아닌 시뮬레이션 데이터 기반
  • 인증/권한 체계 미구현 (credentials hardcoded)
  • 모니터링/알림 파이프라인 없음
  • 부하 테스트/성능 벤치마크 미실시
  • 일부 UI 페이지 미완성 (Page 4 빈 탭)
  • Graph RAG가 아직 Streamlit에 미통합

Overall Verdict

MVP로서 매우 우수. 보험 도메인 이해도가 높고, 단순 대시보드가 아닌 "보험료 산출 엔진 + AI 상담 + 시장 인텔리전스"를 하나의 플랫폼에 통합한 점이 핵심 가치. 특히 7단계 보험료 투명성과 Graph RAG 약관 추론은 실제 InsurTech에서도 차별화 요소로 충분.

프로덕션 전환 시 실데이터 적재, 인증 체계, CI/CD 파이프라인, 부하 테스트가 필요하지만, 이는 MVP 단계에서 기대하기 어려운 영역이며 아키텍처가 이를 수용할 수 있도록 설계되어 있음.
